# 九路电磁阀执行说明

工程版本：V1.7.0.260919。CAN参数表版本：2。日期：2026-09-19。

## 1. 本次确定的行为

- 共控制V1～V9。启动时九个线圈输出和三个12V控制输出全部为低。
- V1～V6独立控制。V7与V9同开同关，与V8互斥；关闭一侧不会自动打开另一侧。
- 新开阀先接通所在组12V，再给该阀线圈通电。吸合窗口为200ms，到期撤销12V，由硬件约5V通路保持。
- V1～V3、V4～V6、V7～V9分别共用一组电压切换。用户允许同组已有保持阀因新开阀短时再次承受12V。
- 每个阀记录独立吸合起点；同组还有阀处于吸合窗口时，共用12V继续有效。同组错峰开阀可能延长该组连续12V时间。
- 重复“打开已开阀”不会刷新计时。关闭正在吸合的阀会撤销其吸合需求；组内没有其他吸合需求时，立即撤销该组12V。
- 本版CAN仍只接受一笔未完成写事务。新开阀在吸合结束、成功转保持后才回复成功；其他写请求返回BUSY，包括吸合期间到来的关闭命令。不是独立的急停通道。

## 2. 原理图依据及引脚

依据`doc/CVD01(Q2)-GS260806CN-V2.0B2.0.pdf`第2、3页。U26产生12VP，U25产生5.5VP；高边MOS导通时输出12V，关断后经D11/D15/D21的二极管通路提供约5V。MCU只切换GPIO和计时，不通过PWM生成5V。

| 信号 | MCU引脚 | 作用 |
| --- | --- | --- |
| VAL1、VAL2、VAL3 | P003、P001、P002 | V1～V3线圈开关，高有效 |
| VAL4、VAL5、VAL6 | P400、P402、P401 | V4～V6线圈开关，高有效 |
| VAL7、VAL8、VAL9 | P410、P411、P408 | V7～V9线圈开关，高有效 |
| VALP1 | P004 | V1～V3共用12V控制，高有效 |
| VALP2 | P000 | V4～V6共用12V控制，高有效 |
| VALP3 | P409 | V7～V9共用12V控制，高有效 |

`configuration.xml`和`ra_gen/pin_data.c`已将P401/P402修正为普通GPIO低输出。现有`R_BSP_WarmStart`在POST_C阶段调用`R_IOPORT_Open`时即应用全部低电平，不等待RTOS任务启动。复位到该阶段之前依赖图纸中的硬件下拉；实际上电瞬态需要示波器验证。任务初始化再次确认十二个GPIO为低输出。

`H_Valve_SetOutputs`使用带掩码的`R_IOPORT_PortWrite`，只更新阀门相关位。V7和V9位于同一个PORT4，使用一次端口写同时更新电平；这不代表两个机械阀的动作时间完全相同。

## 3. 文件与调用关系

阀门模块A/F/H_Valve位于`GS_flowmeter/Valve`；系统协调A_System和A_Control位于`GS_flowmeter/App`。每个C文件都有对应头文件。

| 文件 | 负责内容 | 主要函数 |
| --- | --- | --- |
| A_Valve.c/h | 九阀目标联锁复核、应用接口 | A_Valve_Initialize、A_Valve_SetTarget、A_Valve_Process、A_Valve_Cancel |
| F_Valve.c/h | 先关后开、独立吸合计时、共享电源需求、错误关断 | F_Valve_SetTarget、F_Valve_Process、F_Valve_Cancel |
| H_Valve.c/h | GPIO初始化、逻辑阀位到实际端口位转换 | H_Valve_Initialize、H_Valve_SetOutputs、H_Valve_SetBoost |
| A_Control.c/h | CAN请求授权检查、执行分流、结果和阀状态队列 | A_Control_Process、A_Control_PublishValveState |
| A_System.c/h | 静态资源和八个队列、CAN侧收取状态 | A_System_Initialize、A_System_ReceiveValveState |

```text
上位机 CAN_USER 写请求
  -> A_HostCan_StartWrite：检查参数，形成完整九阀目标
  -> host_command_queue
  -> ControlTask / A_Control_Process：检查请求号、20ms有效状态、3000ms期限
  -> A_Valve_SetTarget：再次检查V7/V9与V8联锁
  -> F_Valve_SetTarget
       1. H_Valve_SetOutputs：先关闭不再需要的线圈
       2. H_Valve_SetBoost：接通新开阀所需12V
       3. H_Valve_SetOutputs：打开新线圈
  -> ControlTask每1ms：A_Valve_Process -> F_Valve_Process
       200ms到期，H_Valve_SetBoost撤销不再需要的12V
  -> valve_state_queue：先发布输出/目标/阶段/故障
  -> host_result_queue：随后发布实际执行结果
  -> HostCanStack：先取新状态，再形成CAN_USER 0x06回复
```

关闭请求和重复打开已保持阀的请求不需要重新等待200ms。阀门请求不进入`command_queue`，不经过MfcTask、RS485或EX201；只有流量写请求走该链路。

互斥切换保证GPIO操作顺序为先关旧侧、后开新侧；没有凭空指定机械释放等待时间。阀门机械关断时间、是否需要气路切换死区尚未确认，不能把电气先关后开视为机械通路零重叠的证明。

## 4. CAN地址与兼容变化

CAN_USER的扩展ID、8字节数据、校验、功能码、32位值编码均保持原协议。`0x0106`参数表版本改为2。

| 地址 | 含义 | 行为 |
| --- | --- | --- |
| 0x0300～0x0305 | V1～V6目标 | 0关、1开 |
| 0x0306 | V7/V9联动目标 | 0同时关闭；1先关闭V8，再同时打开V7/V9 |
| 0x0307 | V8目标 | 0关闭；1先关闭V7/V9，再打开V8 |
| 0x0308 | V9目标查询 | 本版只读，跟随V7；写入返回0x05 |
| 0x0309 | 完整九阀目标掩码 | V7/V9位必须相同且与V8互斥，非法返回0x09 |
| 0x0104 | 九阀已施加输出掩码 | 表示电气输出命令，不代表机械位置；驱动故障时无有效读值 |
| 0x0105 | 阀门阶段 | 0无吸合窗口、1吸合中、2驱动故障；驱动故障时仍可读2 |
| 0x0101 bit0 | 阀GPIO故障锁存 | 1表示输出无法可靠确认 |

新增写结果码`0x13`表示外部阀GPIO操作失败。已有`0x08`表示未就绪，`0x0F`表示原请求失效/超期。旧上位机若写0x0308，需要改写0x0306；原本已使用V7联动入口的程序无需增加V9命令。0x0308虽位于读写uint32区间，本产品明确将它设为只读例外。

## 5. 任务间队列与异常

新增`valve_state_queue`：ControlTask生产，HostCanStack消费，元素为`A_HostCan_System`，长度1，`xQueueOverwrite`按值复制完整九阀快照。它与MFC的六路`telemetry_queue`独立，CAN接收阀状态时保留MFC链路；接收MFC就绪状态时保留阀执行器标志。

`g_valve`是ControlTask独占的静态平铺结构，通过`g_control.p_valve`绑定；CAN任务只能使用出队后的本地副本。未增加阀任务，没有任务间共享阀状态或跨任务调用GPIO。

- 每轮先处理吸合计时，再处理结果队列。结果队列满不能阻止到期撤销12V。
- 尚未完成的阀请求失效时，撤销仍处于吸合窗口的输出，保留之前已经保持的阀，不自动恢复已关闭的互斥侧。已经完成的保持输出不会仅因CAN请求状态变空闲而被关闭。
- GPIO失败时，尽力关闭全部线圈和三路12V，锁存故障、撤销输出有效标志，禁止继续开阀。不以软件写入成功证明实际电压，不在失败后自动重开。
- 已完成命令之后的通信中断停机策略、独立急停及机械反馈不属于本次已实现功能。

## 6. 阅读与调试顺序

先读`A_Valve_SetTarget`的联锁条件，再读`F_Valve_SetTarget`中的三个步骤，最后读`F_Valve_Process`的200ms判断。需要核对引脚时再读`H_Valve_SetOutputs/SetBoost`。

建议观察`g_valve.outputs`、`target`、`pull_in_mask`、`boost_mask`、`started_ms[0..8]`和`fault`；CAN侧观察`g_host_can.system`，两者通过队列同步，短暂差异代表调度延迟。

## 7. 验证与未确认项

本地验证入口：`tests/valve/run.ps1`、`tests/mfc/run.ps1`、`tests/can/run.ps1`。测试目录沿用项目.gitignore规则，不纳入版本控制。

需要实板核对：Q7/Q14/Q21完整型号与极性、实际12V/保持电压、九阀常闭属性及电流、允许的重复升压时长、上电瞬态、机械释放时间、任务栈水位及最坏调度延迟。200ms由ControlTask软件计时；任务或CPU停止运行时，没有独立硬件自动撤销12V的保证。三任务仍各1024字节栈，不能以编译成功代替实测峰值。

测试结果与ARM资源占用记录在README本版本条目中。

# CAN_USER 上位机通信与参数表

工程版本：V1.5.0.260915。参数表版本：1（地址和线上格式保持兼容）。日期：2026-09-15。

## 1. 协议来源与本次范围

以用户提供的 `E:/c/can_module` 为协议基准。本版保留扩展 ID 布局、固定 8 字节负载、校验算法、功能码数值、参数地址小端格式、逐参数读回复及写结果回复。

| 原代码 | 本项目对应实现 |
| --- | --- |
| `CanID_t`、`F_massage_unpack` | `F_CanUser_Encode/Decode`；用移位与掩码替代编译器位域 |
| `H_can_crc_code_fun` | `F_CanUser_Checksum`；保持原算法及截取方式 |
| `F_read_code_deal_fun` | `A_HostCan_HandleRequest`；连续读逐地址返回 |
| `F_write_code_deal_fun` | 保存原请求并等待执行结果，保持功能码0x06及负载格式 |
| 原CAN接收环形队列与驱动 | `H_HostCan`；接入RA4M1 CAN0，使用FSP回调上下文 |
| 原项目的参数switch | 当前文档的六路流量与九阀参数表 |

旧项目的浓度、加热、标定、客户码、握手、复位及多类型节点业务不移入本次固件。广播读写、主动周期上报及心跳保留功能码定义，当前上位机任务不执行这些功能。没有增加新功能码，没有将EX201电文直接封装进CAN。

**本版已接入上位机CAN通信、六路EX201采集及流量写入/读回确认。** ControlTask和MfcTask通过静态FreeRTOS命令/结果队列交接，仅启用MFC执行能力。外部阀门写请求仍返回0x08；九阀驱动、MFC CAN后端和双后端探测尚未实现。已通过模拟六台设备验证，尚未进行实机控制验证。

## 2. 节点与CAN0配置

- 上位机：`Type_Header=0x00`；主板：`Type_FLOW=0x0F`。
- 主板默认CAN节点地址1，由HostCanStack初始化参数指定；节点地址0～126，127保留广播。
- 沿用现有FSP的500 kbit/s配置，需要与上位机实机核对。
- 改为29位扩展数据帧，DLC固定8；邮箱0发送，邮箱1～31接收。
- 接收ID为0x00780000、掩码0x00F80000，只匹配目标类型Type_FLOW。软件进一步核对目标节点地址和来源类型Type_Header。
- configuration.xml与ra_gen/HostCanStack.c同步修改；重新生成FSP代码后检查这几项。
- CAN0与流量计侧MCP2515是两条独立总线。本参数表用于上位机→主板，不直接作为下行CAN设备地址表。

## 3. 帧格式

```text
ID = (function << 24) | (target_type << 19) | (target_address << 12)
   | (source_type << 7) | source_address
```

| 位置 | 内容 |
| --- | --- |
| ID[28:24] | 功能码 |
| ID[23:19] | 目标类型 |
| ID[18:12] | 目标节点地址 |
| ID[11:7] | 来源类型 |
| ID[6:0] | 来源节点地址 |
| D0、D1 | 16位参数地址，低字节在前 |
| D2 | 原协议自定义校验字节 |
| D3 | 参数个数；写请求和单帧回复为1 |
| D4～D7 | 32位值，小端；float采用IEEE-754 binary32位模式 |
| 写回复D4 | 0～255业务结果码，D5～D7固定0 |

校验输入顺序为D0、D1、D3、D4、D5、D6、D7、ID右移24位的字节。初值0xFFFF，逐位右移、多项式0xA001；结果为`(uint8_t)(crc16 >> 4)`。这不是普通CRC8，也不改变RS485仍使用EX201协议的约定。

| 功能 | 值 | 当前处理 |
| --- | --- | --- |
| 写请求 | 0x01 | 定向请求，数量必须为1 |
| 读请求 | 0x02 | 定向请求，数量1～16，地址逐个加1 |
| 广播写/读 | 0x03/0x04 | 当前忽略 |
| 主动周期上报 | 0x05 | 当前忽略；周期查询由上位机重复发0x02 |
| 写回复 | 0x06 | 地址不变，来源与目标互换，返回业务码 |
| 读回复 | 0x07 | 每个参数单独一帧，数量1 |
| 心跳 | 0x08 | 当前忽略 |

原D3可表达更大的数量，本产品初版将单次连续读取限制为16，控制队列和处理时间。非法帧、错误校验、非本机目标及未使用功能不会触发控制。

**读失败处理：** 原协议没有定义通用读错误帧，本版保持0x07仅返回参数，不把错误码放进流量值。一次连续读先验证全部参数，任一参数不存在、无效或过期时，整个请求不发送数据回复，并更新0x010C～0x010E。上位机超时后可读取这三个诊断参数。诊断记录不因成功查询而清除；仅保存最近一次错误，不是错误队列。没有擅自把0x06改成读错误回复。

## 4. 地址分配

每个地址是一个32位参数，地址加1表示下一个参数，不是字节地址。区间两端均包含，未列出的地址预留且拒绝访问。

### 4.1 只读float32：0x0000～0x00FF

| 地址 | 参数 | 有效性与单位 |
| --- | --- | --- |
| 0x0000～0x0005 | 六路实际流量 | 在线、有效，采样年龄不超过2000ms |
| 0x0010～0x0015 | 六路仪器读回设定流量 | 在线且读回有效 |
| 0x0020～0x0025 | 六路满量程 | 量程有效 |

均为工程值，使用对应通道0x0130～0x0135声明的单位。EX201尾数与工程值换算由MFC管理层完成；不隐式混合单位。

### 4.2 只读uint32：0x0100～0x01FF

| 地址 | 参数 |
| --- | --- |
| 0x0100 | 整机状态；默认INIT=0，其他过程状态由ControlTask定义 |
| 0x0101 | 整机故障位 |
| 0x0102 | 六路在线掩码，bit0～bit5对应通道1～6 |
| 0x0103 | 下行链路：0未确认、1RS485、2CAN、3故障 |
| 0x0104 | 外部九阀已施加输出掩码，bit0～bit8对应V1～V9 |
| 0x0105 | 阀门切换状态：0空闲、1切换中、2失败 |
| 0x0106 | 参数表版本，当前1 |
| 0x0108、0x0109、0x010A、0x010B | 固件主版本、次版本、修订版本、日期，当前1、5、0、260915 |
| 0x010C、0x010D、0x010E | 最近出错的参数地址、业务码、原请求功能码 |
| 0x0110～0x0115 | 六路参数有效标志 |
| 0x0120～0x0125 | 六路MFC报警位 |
| 0x0130～0x0135 | 六路EX201单位码：0为cc，1为L，具体流量计标识按设备核对 |
| 0x0140～0x0145 | 六路小数位，0～3 |
| 0x0150～0x0155 | 六路实际流量数据年龄ms；尚无有效样本时为0xFFFFFFFF |
| 0x0160～0x0165 | 六路初始化状态：0未初始化、1进行中、2就绪、3失败 |
| 0x0170～0x0175 | 六路设定来源：0数字、1模拟 |
| 0x0180～0x0185 | 六路内部阀状态：0全开、1调节、2全关、3半开 |
| 0x0190～0x0195 | 六路下行设备通信地址 |

0x0110有效位：bit0实际流量、bit1仪器读回设定、bit2量程、bit3单位、bit4小数位、bit5控制来源、bit6内部阀状态、bit7报警、bit8MCU目标流量、bit9设备地址。这是上位机快照标志，不能直接复制A_EX201_DeviceInfo.valid_flags，二者位定义不同。

外部阀快照未初始化时，0x0104、0x0105和阀门目标寄存器不返回假状态。输出状态不表示机械阀位。运行参数失效时，发布任务负责撤销有效标志或标记离线。

### 4.3 读写float32：0x0200～0x02FF

| 地址 | 参数 | 写入检查 |
| --- | --- | --- |
| 0x0200～0x0205 | 六路MCU目标流量 | 有限、非负、不超过量程、符合本通道分辨率，通道就绪、在线且为数字来源 |

读取值来自MFC发布的已确认目标；V1.5.0在WSFD成功且RSFD读回一致后才发布。CAN入队本身不改写目标、确认值或实际值。尝试WSFD时撤销旧目标及读回有效位，失败时不伪造成功。实际仪器设定从0x0010～0x0015读取；普通周期RSFD读回可以恢复此值，但不会把它冒充成已成功执行的MCU目标。

### 4.4 读写uint32：0x0300～0x03FF

| 地址 | 参数 | 写入值 |
| --- | --- | --- |
| 0x0300～0x0305 | V1～V6目标 | 0关、1开 |
| 0x0306 | V7目标 | 0/1，同时操作V7、V9 |
| 0x0307 | V8目标 | 0/1，与V7/V9互斥 |
| 0x0308 | V9目标 | 0/1，同时操作V7、V9 |
| 0x0309 | 完整九阀目标掩码 | bit0～bit8，其他位必须为0 |

单阀命令转换为合法完整目标后交给ControlTask。V7/V9打开请求令目标V8关闭；V8打开请求令目标V7/V9关闭。关闭一组不会自动打开另一组。完整掩码若V7/V9不一致或两组同时开启，则拒绝。0x0309是全量目标，零位也要求关闭。

CAN层只形成目标，ControlTask必须再次核对当前运行条件、执行先关后开时序，并在输出提交后发布快照和结果；不能直接把目标掩码一次写GPIO绕过切换。所有阀门地址读取同一份控制目标，V7/V9始终一致。

## 5. 本项目业务结果码

| 值 | 含义 |
| --- | --- |
| 0x00 | 实际执行成功 |
| 0x04 | 参数地址不存在 |
| 0x05 | 参数只读 |
| 0x06 | 已有未完成写请求，本次未接受 |
| 0x07 | 目标MFC离线 |
| 0x08 | 执行模块或设备未就绪 |
| 0x09 | 阀门目标违反联锁 |
| 0x0A | 仪器返回NG |
| 0x0B | 下行仪器应答超时 |
| 0x0C | 数据过期 |
| 0x0D | 数量、编码或数值无效，包括NaN/Inf |
| 0x0E | 超出数值范围 |
| 0x0F | MCU等待执行任务提交结果超时 |
| 0x10 | 下行应答协议错误，包括校验、地址/命令不匹配及数据格式错误 |
| 0x11 | 下行驱动或通信恢复失败 |
| 0x12 | WSFD返回OK后，RSFD读回尾数与目标不一致 |

其他值预留。允许执行器提交任意uint8_t结果码，但新增含义必须同步更新本表和上位机。本模块的内部等待状态单独保存，不复用0xFE/0xFF；旧上位机若仍使用它们作为内部超时哨兵，不应随意分配这两个业务码。

## 6. 任务交接与执行确认

```text
HostCanStack → A_HostCan → F_CanUser / F_HostCan → H_HostCan → FSP CAN0
                                  ↓
                          待执行命令及结果槽
                                  ↓
                              ControlTask
                         ↙                 ↘
                   MfcTask              阀门驱动
                      ↓
             EX201 RS485 或下行CAN
```

1. A_System静态持有A_System_Context，其中包含一个A_HostCan_Context和一个六路A_MFC_Context。任务入口取得长期有效指针，向各模块传参；禁止复制上下文或暴露零散可写全局量。
2. MfcTask通过A_System_ProcessMfc推进采集，以A_HostCan_PublishChannel在临界区内发布有变化的通道快照；CAN晚启动时自动补发。A_HostCan_PublishMfcLink仅更新链路字段，ControlTask的A_HostCan_PublishSystem保留该字段，双方不会互相覆盖。仅任务调用，不能从ISR调用。
3. A_System创建两个长度1的静态FreeRTOS队列，MfcTask确认队列及采集上下文已接入后，A_Control只启用A_HOSTCAN_EXECUTOR_MFC。单设备在线和初始化条件仍逐命令检查；阀门执行标志不启用。
4. ControlTask非阻塞调用A_HostCan_TakeCommand，只能领取一次。流量命令包含通道索引和float32位模式，阀门命令包含归一化后的完整目标。
5. 执行前调用A_HostCan_CommandActive检查请求号和期限；再执行过程联锁。CAN参数检查不能代替ControlTask过程检查。
6. ControlTask将解析后的A_MFC_Command按值入命令队列，MfcTask等待当前轮询结束后重新验证条件，读RFSM确认数字来源，换算尾数并调用A_EX201_SetFlow单次写WSFD，然后读RSFD确认。结果按值进入结果队列，ControlTask检查请求号后调用A_HostCan_CompleteCommand。
7. CompleteCommand只提交结果，不发送CAN；HostCanStack在下一轮用原请求地址和来源节点回复0x06。
8. 默认同时保留一个未完成写请求；忙时返回0x06业务码。上位机应串行下发修改命令，查询可以继续进行。执行期限3000ms，从CAN接受时算起；超时或CAN恢复后旧请求号失效，不重放旧写命令。上位机等待回复建议至少3500ms。已开始的物理动作不能凭请求失效自动撤销。
9. 写成功仅表示设定/输出操作已确认，不表示流量达到目标或机械阀到位。超时可能对应结果不确定，需要读回确认。
10. 应用层不自动重发写请求。线上没有事务序号，上位机重新发送同一请求仍可能形成新事务，不能宣称严格执行一次。

## 7. 资源与验证

接收队列16帧，回复队列32帧；每次最多处理4个请求，单次读取上限16个参数，发送邮箱忙时不阻塞任务。HostCanStack每1ms推进一次，当前工程1000Hz节拍；修改节拍需同步修改毫秒换算。

CAN发送100ms未完成或发生bus-off/发送中止时，关闭重开外设并丢弃旧队列，恢复失败按100ms退避重试。没有持续等待循环，不在中断中解析协议、延时或操作业务。

本机测试命令（工作区根目录）：

```powershell
./tests/can/run.ps1
./tests/mfc/run.ps1
```

测试覆盖新旧校验算法1024组对比、ID与小端布局、地址边界、uint32高位、非法帧、接收溢出、六路连续读取、无效/过期读取诊断、异步写回复及请求来源关联、自定义返回码、阀组目标归一化与非法组合、执行超时、迟到结果和发送恢复。测试FSP/临界区替身不能代替实机中断时序和电气验证。

## 8. 六路采集与上位机周期查询

MfcTask独立在RS485总线上轮询六台EX201，默认地址001～006全部启用；CAN查询只读取已经发布的缓存。实际流量每路目标500ms查询一次；RSFD、RFSM、RVSS、RCVS、RALM每路每1000ms轮换一项，每项约5s查询一次。量程、小数位和单位在初始化及掉线恢复时重读。实际刷新受串口速率、设备响应和超时负载影响。

CAN实际流量、读回设定及满量程使用该路小数位进行除以10的幂的换算，单位由该路RFRU决定。RVSS数字阀设定保存在A_MFC_Channel.device_info中，目前未增加其独立CAN地址；0x0180～0x0185仍返回RCVS实际阀状态。MCU目标值0x0200～0x0205只在对应写请求成功并读回一致后有效。

在线表示近期有效通信且未达到离线条件；不表示已完成全部参数初始化。初始九项全部读回后，0x0160～0x0165才变成2。单次错误立即撤销对应字段有效位；初始化失败或就绪后连续3次失败进入离线，5s后重新初始化。0x0103仅根据当前EX201路径报告待确认、RS485或故障，暂不会报告已确认下行CAN。

上位机可以周期发送功能码0x02、起始地址0x0000、数量6，正常时收到0x0000～0x0005的六帧0x07回复。任何一项离线、无效或过期时仍遵循整组拒绝规则；先读取0x0102在线掩码，再逐路读取可避免一台离线导致其他五台无法显示。仅在线也不保证某字段有效，可同时查询0x0110～0x0115有效位及0x0160～0x0165初始化状态。

详细轮询顺序和验证方法见[六路MFC轮询说明](六路MFC轮询说明.md)。

## 9. 流量写入要求

收到0x01后不会立即回复成功。执行顺序为等待当前轮询结束→RFSM→WSFD→RSFD→发布确认缓存→结果队列→0x06回复。RFSM必须表明数字控制；本版不发送WFSM切换来源，不操作内部阀设定或外部电磁阀。

工程值乘以10的小数位次方后必须可表示为四位整数尾数，仅容许float32乘法误差，不任意舍入。小数位1时12.3有效，12.34返回0x0D。量程上下限也在MfcTask执行前重新核对。

写超时可能意味着设定已经生效但应答丢失，固件不会自动重发。RSFD读回不同值时返回0x12，并允许通过0x0010～0x0015读取仪器真实设定；目标有效位保持撤销。CAN中断报告的硬件故障会使执行授权检查失败，即使HostCanStack还没进入恢复处理，也不能再启动WSFD。

新增集成测试包含六路写入、忙请求、错误分类、数字来源变化、无提前成功回复、队列满与旧结果关联、超过1500ms的慢响应和时间回绕。详细说明见[流量写入执行说明](流量写入执行说明.md)。

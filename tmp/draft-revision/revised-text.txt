引言
编写目的
本文定义基于 R7FA4M1AB3CFM 的六路质量流量计控制系统初步软件方案，用于硬件接口核对、固件开发和联调。MCU 通过 RJ45 连接的 RS485 总线向六台 EX-201S 系列质量流量控制器下发流量设定并读取运行参数，同时管理九个外部电磁阀。上位机通过 CAN 和以太网两种接口控制 MCU，并读取当前设备状态、阀门状态及流量计参数；以太网使用独立 RJ45 网口。[S6]
初步方案采用一条 MFC 下行总线、六个独立通道对象和统一阀门联锁。MFC 内部完成流量闭环，MCU 负责设定、监测与过程协调。上位机可经 CAN 或以太网完成检测与过程协调，MCU 统一校验并执行请求，始终保留本地阀门联锁和故障关断职责。已知要求、设计建议及待确认参数在各节分别注明。
项目背景
气路由六条支路经流量计汇入混气管，其中五路为常规使用气体，第六路预留。V1 至 V6 为支路阀，混气管后配置 V7、V8、V9，用于正常输出和排空、校准或测试气体通路。V7、V8 中任一阀开启时，V9 不可开启；V9 开启时，V7、V8 均不可开启，形成互斥。各允许组合与具体工艺模式的对应关系另行确认。[S3][S6]
项目核心约束为：采用瑞萨 R7FA4M1AB3CFM，48 MHz Arm Cortex-M4F 内核，256 KB Code Flash、8 KB Data Flash、32 KB SRAM；系统待机功耗必须小于 100 W；产品应满足长期可靠性要求，在 −10 ℃ 至 +40 ℃ 环境温度下稳定工作。功耗按项目指标验收，测量边界和条件需冻结；系统环境指标与 MFC 自身允许温度的适配见第 2.3 节。[S5][S6]
系统目标是保证流量计数据及时传输、设定可靠执行，以及阀门控制的实时性和安全性。上位机通过 CAN 或以太网控制和监测 MCU，MCU 通过 RJ45 承载的 RS485 控制和读取六台 MFC，组成统一的控制与状态反馈链路。
阅读人员
适用人员包括嵌入式软件开发、硬件设计、气路与工艺设计、上位机开发、测试及现场调试人员。硬件负责输出极性和断电状态，软件负责时序和异常处理，工艺负责气体组合及实际流量验收条件。
术语定义

软件需求概述
项目简介
六台 MFC 使用独立地址接入同一条半双工 RS485 总线，由 MCU 逐台访问。软件维持设定流量、实际流量、气体类型、满量程、内部阀状态、设备报警和通讯状态。V1 至 V6 与对应 MFC 成对管理，V7 至 V9 统一联锁。CAN 与以太网作为独立上行接口，共用同一业务接口和状态缓存，上位机请求经 MCU 转换为下行事务。

设计目标
功能项初步设计要求参数读取读取六路实际流量、设定值、气体类型、量程、小数位、单位、流量基准温度、内部阀状态及设备报警。流量控制每路独立启停和设定；写入后回读确认；对超量程、未就绪、未获许可及低于可控范围的非零设定返回明确错误。通路控制统一管理 V1 至 V9；V7 或 V8 开启时禁止 V9，V9 开启时禁止 V7 和 V8。所有本地与远程入口执行同一互斥规则。异常处理对超时、校验错误、设备 NG、流量持续偏差、设备报警和手动关闭分别处理，禁止把无效流量当作零流量。恢复管理复位后默认关断；重连先核对参数和状态，再等待新的启动请求。可维护性驱动、协议、通道和业务分层；硬件极性、阈值及延迟可追溯。上行控制与监测同时提供 CAN 和以太网接口，读取整机、阀门与六路 MFC 状态；支持上位机协调，执行结果经 MCU 确认后返回。待机功耗系统待机功耗必须小于 100 W，按确认的测量边界与待机负载实测。环境与可靠性整机在 −10 ℃ 至 +40 ℃ 环境稳定工作；完成仪表温度适配及长期运行验证，验收时长待确认。

建议六路流量刷新周期不大于 1 s，内部阀状态及 MFC 报警刷新不大于 2 s，需在 9600 bps 下实测。外部阀联锁在每次请求和输出更新前本地执行；上行接收、执行、完成与实际关断时间分别记录并冻结。MFC 典型响应约 1 s 属于仪表动态特性，不等同于指令完成或混气稳定时间。[S2]
设计平台
项目已知参数或拟定选择MCUR7FA4M1AB3CFM，RA4M1，64 引脚 LQFP，48 MHz Arm Cortex-M4F；256 KB Code Flash、8 KB Data Flash、32 KB SRAM。[S4][S5]MFC 通讯SCI2：P302/TXD2、P301/RXD2；9600 bps、8N1，六台共用。[S1][S4]上行通讯CAN 与以太网两种独立接口。CAN 收发器及装配待核对；以太网须补充外接控制器或模块、网口及 MCU 引脚资源。[S4][S6]软件工具建议 e² studio、Arm GCC、Renesas FSP；版本在建工程时锁定。调度与存储中断收发与非阻塞主循环，静态内存；片内 Data Flash 保存低频配置。

MCU 提供 4 路 SCI/UART 和 1 路 CAN，无片内以太网控制器。[S5] 六台 MFC 共用 SCI2。以太网须补充外接控制器或模块及所需 PHY、隔离磁性器件和独立 RJ45 网口，具体方案见第 4.5 节；仅加 PHY 或改用现有 RS485 RJ45 不能实现以太网。
EX201 使用温度为 5 ℃ 至 50 ℃，精度保证温度为 15 ℃ 至 35 ℃。[S2 印刷页 7] 满足整机 −10 ℃ 至 +40 ℃ 目标需确认相应等级的设备，或通过保温、加热及散热使仪表局部环境符合规格，并验证低温启动、高温运行和计量性能；温控耗电纳入待机预算。

软件架构图
CAN / 以太网接收 → 协议适配 → 控制权与参数校验 → 整机状态机 → 通道事务及阀门仲裁 → EX201 协议与总线调度 / GPIO 驱动。设备响应更新统一状态缓存，经 CAN 或以太网返回上位机。上位机可计算配比、检查状态并组织流程；MCU 对每次执行独立检查许可、互斥与数据有效性，所有命令入口均不得直接改写阀门 GPIO。
串口、CAN 及以太网相关中断仅处理必要的收发、事件和时间戳，不执行整机状态切换或 Flash 擦写。主循环优先处理硬件停机条件与阀门联锁，再处理收发解析、阀门计时、事务、轮询、上行请求和后台存储。各任务及队列均设上限；网络突发流量不得阻塞本地保护和 RS485 调度，队列满时返回忙或丢弃低优先级遥测并计数。

供电与控制优先级
EX201 +24 V 版本的 DB9 pin3 为电源输入、pin4 为电源 COM；应按实物铭牌核实电源版本。手册给出 +12 至 +24 V、单台 300 mA 以下的条件，六台按 300 mA 保守估算为 1.8 A；24 V 下约 43.2 W。原理图 MFC 电源模块标注 60 W，仍需校核启动、温升、线损及保护余量。[S2][S4]
上述 43.2 W 是六台 MFC 的保守供电估算，不能作为整机待机功耗结论。待机建议定义为无气体输出、外部阀关闭、MCU 及上行通讯可用；MFC 是否持续预热须明确。以整机输入端测量小于 100 W 为验收目标，统计控制板、MFC、通讯模块、阀驱动和温控等负载；仪表是否包含在测量边界及适用能效标准编号由需求确认。
DB9 pin1 的外部强制信号优先于数字设定：开路为控制、接流量输出 COM 为全关闭、输入 +5 至 +24 V 为全打开。建议正常运行保持“控制”，如采用硬件强制关闭，使用经电平匹配的开漏或隔离电路；禁止将 +24 V 直接送入 MCU 引脚。失去通讯时不能假定 MFC 自动归零，外部关断能力必须独立验证。[S2 印刷页 11]
EX201 通讯协议模块
总线与电文格式
下行使用 EX201 自定义 ASCII 协议，默认 9600 bps、8 数据位、无校验、1 停止位；若设备 OPTION 铭牌另有标注，以铭牌为准。主站同一时刻只允许一笔未完成事务。地址拨码建议分别设为 01 至 06，报文编码为 001 至 006。[S1 印刷页 5 至 7]
方向字段顺序说明请求@ + ID(3) + CMD(4) + DATA(n) + SUM(2) + CR@ 为 0x40；数据长度由命令决定；CR 为 0x0D。响应% + ID(3) + CMD(4) + OK/NG(2) + DATA(n) + SUM(2) + CR% 为 0x25；写命令通常无数据，但仍应收到结束代码及校验。校验SUM = 所有起始符至数据字节之和的低 8 位将结果转换为两位大写十六进制 ASCII；不包含 SUM 自身及 CR。

接收采用“找 % → 累计至 CR → 验证长度、校验、地址、命令与结束代码 → 解析数据”的状态机。缓存初值可取 64 字节；过长帧、无效字符、串口溢出和未结束帧均丢弃并记录。发送方向在最后一个停止位真正发完后切回接收，不能在发送缓冲区空时提前切换。
核心命令表
命令用途数据与约束RMFS / RDPP / RFRU读满量程、流量小数位、单位RMFS：4 位 0001 至 9999；RDPP：0 至 3；RFRU：0=cc，1=L。RFRC / RCGT / RRMD读基准温度、气体、动作模式温度 00/20/25；气体 0 至 8；模式 1=校准气体、2=CF 换算、4=多气体。RFSM / WFSM读写流量设定来源0=数字，1=模拟；启动前确认数字模式。WSFD / RSFD写入及回读数字设定流量WSFD 写 4 位尾数 0000 至满量程尾数；RSFD 读取 4 位尾数。RCFR读取瞬时流量按带符号尾数解析，小数位与单位来自设备参数；长度歧义见第 4.9 节。WVSS / RVSS设置及读取数字内部阀状态0=全开，1=流量控制，2=全关；常规界面不提供强制全开。RCVS / RCVO读取内部阀状态与开度RCVS：0/1/2/3 对应全开/控制/全关/50%；RCVO：0000 至 1000，单位 0.1%。RALM读取报警位掩码1=传感器异常，2=阀过热，4=设定值存储异常；多项可相加。RALA / WALA读取与设置设备报警动作建议配置 1=强制全关并回读；仅对设备报警有效，不能据此推断通讯失联动作。RRDP / RPCF / RCCF读取差压档、校准 CF、当前 CF只作参数显示与核对；变更差压、模式及 CF 限于受控维护。ZERO传感器调零仅维护模式、流路隔离并满足零差压条件时执行，不自动重试。

首版不向用户开放未确认命令。RCFS 可作为实际设定来源诊断读取；RSFR 与 RAZS 在手册中的方向说明存在疑点，暂不用于启动和闭环依据。软件只使用已经完成单机验证的命令与严格匹配的数据格式。[S1]
流量换算与设定事务
设备流量 = 带符号尾数 × 10^(−小数位)。若 RFRU=0，界面按 cc/min 或 mL/min 显示；若 RFRU=1，按 L/min 显示。统一到 mL/min 时，L/min 数值乘 1000。显示必须同时保留 RFRC 的基准温度条件，不能把不同基准条件的体积流量直接当成相同计量条件。
示例：RMFS=1000、RDPP=1、RFRU=0 时，满量程为 100.0 mL/min。用户设定 25.0 mL/min，对应 WSFD 数据 0250。换算使用整数定点或受控舍入，先检查有限值与上下界，再格式化为固定四位数字。
零设定允许用于停止；非零常规设定限定在设备 2% 至 100% F.S. 可控范围内。手册指出 1% F.S. 以下按全关闭处理，而 2% 以下控制不保证，因此界面拒绝 0 与 2% F.S. 之间的非零设定，不能静默修正为其他值。[S1 印刷页 3、13]
设定事务分为“接受请求、发送写命令、收到 OK、回读匹配、完成”五步。保存 requested_setpoint 与 confirmed_setpoint；只有 WSFD 得到有效 OK 且 RSFD 回读一致，才更新已确认设定。回读失败或不同步时标记执行结果未知或校验失败，禁止只因串口发送成功就显示已生效。

轮询与异常重试
轮询采用轮转队列：RCFR 为快速项，RALM、RCVS、RSFD 为慢速项，量程与气体参数在初始化、维护变更或重连时读取。停止请求优先于普通写入，普通写入优先于低频查询；同一路待发送设定可合并为最新值，已开始的事务必须有明确结束结果。
9600 bps、8N1 下每字节约 1.042 ms。一次 RCFR 请求为 11 字节，按“符号加四位数字”的响应为 18 字节，纯传输约 30.2 ms；六路至少约 181 ms，尚不含从站处理、方向切换和慢速查询。建议响应超时初值 150 ms、帧间余量 5 ms、只读重试最多 1 次，现场测量后统一调整。
单通道建议连续 3 次事务失败置离线，快速数据超过 3 s 未更新置陈旧；这些是可调联调初值，不是手册保证。离线设备进入低频探测，不能持续阻塞健康通道。在线运行通道失去有效数据时，按整机故障策略停机，不等到无限重试。
写入超时后先回读目标参数再决定是否重发；对 ZERO 不自动重试。超时后清空旧事务并设置恢复窗口，在确认接收空闲后再发新请求。协议没有事务序号，相同地址和命令的迟到响应可能无法区分，必须通过受控串行、清理迟到帧和回读最终值降低歧义。

启动与停止
启动前确认参与通道启用、气体和量程匹配、预热完成、无锁定故障、手动许可有效，并选定经工艺批准的公共通路组合。保持 V1 至 V6 关闭，逐台确认 WFSM=0、WVSS=2；写入目标 WSFD 并回读 RSFD，再按第 4.4 节先关后开建立合法的 V7/V8 或 V9 通路，依次切到 WVSS=1 并开启参与支路。通路模式尚未批准时禁止启动；任一步失败均进入停止流程。
以上为建议顺序，最终开阀先后和等待时间应依据压差及阀门机械响应确认。多个通道无法在单总线上实现严格同步写入，启动阶段存在时间差；若工艺要求无过渡配比误差，应增加受控旁路或硬件同步机制，不能用“批量写成功”代替同时生效。
正常停止先关闭参与支路的外部阀，同时排队发送 WVSS=2 和 WSFD=0000，再按已确认的关断时序关闭当前开启的 V7 至 V9，使所有外部阀最终处于关闭状态。故障停止立即撤销全部外部开阀输出，再尽力关闭各 MFC；通讯不可用时仍完成外部关断。停止不自动排空，泄压和对应路径由独立工艺流程定义。
运行与恢复
RUNNING 周期检测设定回读、实际流量、内部阀状态及报警。流量偏差判定可采用 |Q实际−Q设定| > max(绝对阈值，相对阈值×Q设定) 并持续指定时间；启动、改设定及通路切换后的稳定等待单独计时，不能将仪表正常响应过程误判为故障。阈值、持续时间和稳定等待在实机上标定后冻结。
初版建议运行中任何参与通道发生严重故障即停止整套混气，避免剩余气路改变配比；未参与且已停用通道离线只提示。故障解除后重新读取设备参数、确认全关和零设定，进入 READY；必须收到新的启动请求，禁止自动恢复上次非零设定。

分组电源与切换时序
原理图存在 12 V 吸合与约 5 V 保持的分组供电路径，每组三阀共享 VAL/Px。软件应为每组设置吸合计时器：任一阀新开触发该组吸合电压，在确认的吸合时长结束后转保持电压；同组再次开阀时重启或延长组计时，不能被另一通道提前降压。具体电平对应、电压和最长吸合时间由硬件与阀厂确认。[S4 第 2、3 页]
V7/V8 组与 V9 之间切换采用先关后开：隔离进气并将设定归零 → 关闭旧通路 → 等待关断确认或经验证的最坏关闭时间 → 复核互斥和工艺许可 → 开启新通路。阀门管理器串行执行整组事务，包含已接受但尚未输出的开阀动作；新停止请求取消未完成的开启动作，迟到命令不得重新开阀。无反馈时须显式标记实际阀位未确认。

## 自编代码分层命名规则

自 2026-09-14 起，项目自行编写的 C 模块按职责使用固定前缀，源文件、头文件及其函数必须保持同一层级前缀：

| 层级 | 文件前缀 | 函数前缀 | 职责 |
| --- | --- | --- | --- |
| 用户/业务逻辑层 | `A_` | `A_` | 业务请求、事务状态机、通道管理和对任务提供的业务接口 |
| 功能逻辑层 | `F_` | `F_` | 协议编解码、数据转换、校验和不直接操作硬件的通用功能 |
| 硬件逻辑层 | `H_` | `H_` | MCU外设、GPIO、UART、SPI、CAN及具体硬件驱动 |

每个自行编写的 `.c` 文件必须配套同名 `.h` 文件，包括内部 `static` 函数在内的函数均使用所属层级前缀。例如，EX-201S 模块分为 `A_EX201.c/.h`、`F_EX201.c/.h`、`H_EX201.c/.h`。FSP 自动生成的 `ra_gen` 文件和任务入口文件保留配置器生成的名称，避免重新生成时被破坏；FSP 中允许配置的用户回调函数仍采用相应的 `H_` 前缀。

结构体与变量统一遵守以下规则：

- 结构体类型名应简明表达模块职责，各单词首字母大写并用下划线分隔，例如 `A_EX201_Context`、`F_EX201_Response`。结构体实例以小写 `g_` 开头，例如 `g_ex201_context`。
- 结构体成员使用能够表达用途的小写蛇形命名。用于保存到存储器的 `Save` 结构体，其单个成员不得超过 32 位，并且至少包含一个明确的 32 位成员，以保证按 32 位边界组织数据；数组元素的基本类型也不得超过 32 位。
- 仅在当前 `.c` 文件使用的普通文件级变量必须声明为 `static`，使用全小写 `s_` 前缀。模块运行状态不得拆成多个文件级变量；确有长生命周期需求时，将状态集中到一个 `g_` 结构体上下文，并由任务持有、通过指针传入各层接口。
- 尽量使用局部变量和函数参数传递数据。接口不得依赖隐藏的可写全局状态；上下文结构体必须由调用者创建，函数通过结构体指针读写状态，以便同一模块创建多个实例并便于移植。
- 头文件仅放置接口需要的宏、条件编译、类型定义和函数声明，不放置变量定义、函数实现、内联业务处理或其他执行逻辑。

函数依赖必须逐层调用：

```text
任务入口 → A_应用层 → F_功能层 → H_硬件层 → FSP/HAL
```

- `A_` 函数可以调用本模块的 `A_` 私有函数、`F_` 接口以及其他模块公开的 `A_` 接口，不得直接调用 `H_` 接口。
- `F_` 函数可以调用本模块的 `F_` 私有函数和 `H_` 接口，不得调用 `A_` 接口，也不得绕过 `H_` 直接操作 FSP 外设。
- `H_` 函数负责调用本模块的 `H_` 私有函数及 FSP/HAL 接口，不得反向调用 `F_` 或 `A_` 接口。
- FreeRTOS 任务入口负责创建并持有业务上下文、提供系统节拍及调度 `A_` 接口；协议状态机不直接取得系统节拍，避免把操作系统依赖扩散到功能层和硬件层。

本项目使用 R7FA4M1AB3CFM 管理六台 EX-201S 系列质量流量控制器和九个外部电磁阀。流量闭环由流量控制器内部完成，MCU 负责流量设定、状态采集、气路过程协调及阀门联锁，上位机负责操作和监测。

本文将信息分为“原理图确认”“用户装配说明”“软件建议”和“待确认”。原理图不能替代实板装配和电平验证。当前 Word、流程与架构图统一按 V1.2.0.260911 修订；此前文档作为历史依据保留，不再用于当前协议实现。

**2026-09-11 最新通信方案：MFC RS485 使用 EX-201S 仪器自带专用 ASCII 协议，MFC CAN 使用用户自定义 CAN_USER；同一固件同时保留两个后端，由 MfcTask 运行时探测、确认并锁定有效链路。此前 Modbus RTU 和预编译二选一方案均已被取代。** 两个 RJ45 和一个 DB9 仍共用一条下行总线，外接三选一；J17/J18 继续由人工统一选择物理总线。

**2026-09-11 阀门联锁更新：V7 与 V9 同步开关，组成一个逻辑阀组，与 V8 互斥。** 当前联锁以这条用户最新说明为准，具体规则见第 8 节。

**通信资料适用范围：** EX201 说明书485通讯.pdf 为当前 RS485 协议依据；CAN_USER 名称和归属已确认，具体报文与兼容对端仍需落实。RS485 标准为 9600 bit/s、8N1，OPTION 标签优先；命令、流量换算和手册歧义见第 7 节。

## 2. 上位机接口核对

### 2.1 连接关系

原理图第 1、2 页显示：

```text
上位机
  ↕
J1 / J2 DB25，共用 OUT/H/485B、OUT/L/485A
  ↕ 保护与滤波电路
U5：TCAN1042VDRQ1 CAN 收发器
  ↕ U4：ADUM1201 数字隔离
MCU：CAN_TXD0 / CAN_RXD0，内置 CAN0
```

原理图还画有 U2（SP3485EN）作为 RS485 路径。根据用户提供的实际装配情况，U2 未焊、U5 已焊，因此当前上位机接口按 CAN 使用。J1/J2 共用 U5，不能视为两个独立 CAN 通道；两个接口还带有电源等引脚，并非全部引脚都用于通信。

### 2.2 J1/J2 通信相关引脚

以下为原理图引脚编号；制作线束时须区分连接器插接面与焊接面的观察方向。

| 两个 DB25 的引脚 | 原理图网络 | 当前 CAN 用途 |
| --- | --- | --- |
| 2、15 | OUT/H/485B | CANH |
| 3、16 | OUT/L/485A | CANL |
| 1、14 | GND3 | 通信侧参考地 |
| 5、6、7、18、19、20 | 24VP | 电源网络，不能当通信脚使用 |

### 2.3 使能、终端电阻与装配注意点

- `RS485_EN0` 经 U3 控制 U5 的 STB。名称虽带 RS485，当前上位机 CAN 装配仍需初始化此信号。
- `RS485_RES0` 经 U3、U6 控制 R16（120 Ω）终端电阻，根据本板在总线中的位置配置。
- U4 的 MCU 侧存在 CAN 引脚与备用 UART 引脚的电阻连接路径。须核对 R8、R9、R11、R13 的实际装配；CAN 使用期间，不能同时将备用 `RS485_TXD0` 配置为活动 UART 发送输出。
- U5 的 STB 低电平为正常通信，高电平为待机。MCU 到隔离侧的实际电平和上电默认状态需实测确认。芯片模式依据 [TI TCAN1042-Q1 数据手册，第 9.4 节](https://www.ti.com/lit/gpn/tcan1042-q1)。

## 3. 流量计接口核对

### 3.1 三个端口共用同一条总线

J9、J15、J10 的通信线均接到同一组 `H/B`、`L/A` 网络。三口之间没有接口选择开关，也没有各自独立的收发器。

用户要求的“RJ45 或 DB9，三选一”属于产品接线约定：使用其中一个端口接入六台流量计所在的总线。软件无需按 J9/J15/J10 分成三个驱动。其余端口在电气上仍连接同一条总线，不能另接一种协议的设备网络。

| 板端接口 | H/B | L/A | 其他相关引脚 |
| --- | --- | --- | --- |
| J9 RJ45 | 4 脚 | 5 脚 | 1、2 脚为 GND4；3、6、7、8 脚未接通信信号 |
| J15 RJ45 | 4 脚 | 5 脚 | 1、2 脚为 GND4；3、6、7、8 脚未接通信信号 |
| J10 DB9 | **1 脚** | **2 脚** | 3 脚为经保护的 24V5；4 脚为 GND5；5 脚为 FG；6、7、8、9 脚未接 |

**修正：J10 的 L/A 是 2 脚，7 脚未接。** 不能沿用此前将 7 脚写为通信脚的记录。

流量计说明书中的设备 RJ45 为 1/2 脚 TR_COM、4 脚 TR−、5 脚 TR+。板端 H/B、L/A 的命名不能直接代替器件极性核对，须结合下面的 0 Ω 电阻装配确认线束。

板上 J10 的定义也不能套用流量计本体 DB9 的定义：设备 DB9 承担电源和模拟控制等信号，不能假设一根 DB9 直通线即可完成数字通信。选用板端 DB9 时，应单独出具至设备通信接口的线束表。GND4、GND5、FG 的连接按隔离和接地方案核对，不默认短接。

### 3.2 J17/J18 的选择关系

| 工作方式 | J17 短接 | J18 短接 | 连接的收发器 |
| --- | --- | --- | --- |
| CAN | 1–2 | 1–2 | U22 的 CANH / CANL |
| RS485 | 2–3 | 2–3 | U17 经电阻配置后的 H_485B / L_485A |

J17 的 2 脚、J18 的 2 脚分别进入公共滤波与保护电路，再连到三个端口。两只跳线需要人为设置一致，并非机械联动开关。跳线方向以 PCB 的 1 脚标识为准，不能仅凭“上面/下面”判断。

图中没有用于直接读取 J17/J18 状态的 MCU 检测信号，因此固件不能读取跳线位置，也不能通过软件改变跳线连接。固件可以通过完整且校验正确的 EX-201S 应答或 CAN_USER 报文间接识别有效链路，但识别结果不能代替生产和调试时对“跳线、器件装配、设备协议、线束”的人工核对。

U17 的 A/B 另有 0 Ω 电阻换向配置：R17 + R148 对应 B→H_485B、A→L_485A；R14 + R149 对应交叉连接。须核对实际焊接，四只不能全部导通，否则会将 A/B 相连。

### 3.3 RS485 路径

当前协议为 EX-201S 仪器自带的专用 ASCII 协议。MfcTask 作为主站事务调度者，经 SCI2 控制 RS485 收发；六台流量计作为从站响应请求。

```text
MCU SCI2：MFC_TXD2 / MFC_RXD2
  ↕ U21 ADUM1201
U17 SP3485EN
  ↕ A/B 电阻配置
J17、J18 均短接 2–3
  ↕ 公共滤波、保护电路
J9 / J15 / J10 → 六台流量计的共享总线
```

`MFC_EN2` 用于收发控制相关电路；`MFC_RES2` 控制共用终端电阻。半双工发送必须等待 UART 最后一个停止位真正发送结束，再按经实板验证的控制电平切换接收，不能仅以发送缓冲区为空作为切换条件。

### 3.4 CAN 路径

```text
MCU SPI：MOSI / MISO / SCK / NSS
  ↕
U11 MCP2515-I/ST：独立 CAN 控制器
  ↕ MFC_CTXD / MFC_CRXD，经 U23 ADUM1201
U22 TCAN1042VDRQ1：CAN 收发器
  ↕
J17、J18 均短接 1–2
  ↕ 公共滤波、保护电路
J9 / J15 / J10 → 实现 CAN_USER 的下行对端总线
```

- U11 完成 SPI 与 CAN 控制器之间的接口功能，U22 完成 CAN 物理层收发，两者功能不同。
- U11 的 Y1 标为 **8 MHz**。CAN 位时序计算应使用该振荡器频率，不能套用常见 16 MHz 模块的参数。
- 第 2 页中 U11 的 **INT（13 脚）未画出到 MCU 的连接**，RX0BF/RX1BF 同样未接。因此当前板型先采用 SPI 定时读取接收/错误状态的方案，不能假定已有 MCP2515 外部中断通知。
- U11 RESET（19 脚）由 R26/C44 构成上电复位相关电路，未显示 MCU 复位控制 GPIO。
- MCP2515 是经典 CAN 控制器。它只有两个接收缓冲区，SPI 轮询周期须结合 CAN 波特率、过滤规则、最大突发报文量和任务调度延迟验证。不能因为收发器支持更高能力就将本系统定义为 CAN FD。依据 [Microchip MCP2515 数据手册](https://ww1.microchip.com/downloads/en/DeviceDoc/MCP2515-Stand-Alone-CAN-Controller-with-SPI-20001801J.pdf)。

### 3.5 MFC_EN2 与 MFC_RES2：两个后端都需要保留

原理图第 3 页中，`MFC_EN2` 经 U7 同一只光耦晶体管影响两个**不同的电气节点**：

| U7 节点 | 网络与作用 |
| --- | --- |
| 12 脚，集电极 | MFC/EN，经 R98 到 U17 的 DE 和 /RE；R100 上拉至 5V4 |
| 11 脚，发射极 | CAN/STB，到 U22 的 STB；R113 下拉至 GND4 |

所以 CAN 链路仍需要处理 `MFC_EN2`，但它不作为逐帧的 RS485 收发方向信号使用，而是服务于 CAN 收发器的工作模式控制。运行时探测会在两种控制需求之间切换，必须先通过实板测量确认两个节点的有效电平和安全切换顺序。

**待实板核对：这不是发射极直接接地的普通反相光耦电路。** 输入低、光耦截止时，两个输出分别由上拉和下拉电阻决定；输入高、光耦导通时，集电极与发射极间导通。如果 R100、R113 均按图中的 4.7 kΩ 装配，可能出现分压，不能直接假定 MFC/EN 能可靠拉低或 CAN/STB 能可靠拉高。需核对实际装配并测量两个输出电压，对照 U17/U22 的输入门限，之后才能确定驱动层的有效电平。

`MFC_RES2` 经 U7、U24 控制 R138（120 Ω），电阻跨接公共总线，RS485 和 CAN 模式均适用。它是终端电阻控制信号，不是 MCU、流量计或 MCP2515 的复位信号。终端配置按总线位置确定，不因板上有三个插座就启用三份终端。

## 5. 运行时链路识别方案

上位机固定为 MCU 内置 CAN0。MFC 固件同时包含两套总线后端及其匹配的应用协议，由 MfcTask 独占两个外设并管理运行时识别：

| 候选链路 | MFC 传输后端 | 应用协议 | 物理接通条件 |
| --- | --- | --- | --- |
| RS485 | SCI2 经 U21、U17 | EX-201S 自带 ASCII 协议 | J17/J18 均 2–3 |
| CAN | SPI1 经 MCP2515、U23、U22 | 用户自定义 CAN_USER | J17/J18 均 1–2 |

```c
typedef enum
{
    MFC_LINK_DETECTING = 0,
    MFC_LINK_RS485,
    MFC_LINK_CAN,
    MFC_LINK_FAULT
} mfc_link_type_t;
```

总线和协议仍是一一匹配关系，不允许 RS485 选择 CAN_USER 或 CAN 沿用 EX-201S 串口电文。探测阶段只能发送读取状态、读取设备信息等无副作用命令，并保持外部阀关闭和流量设定为零。RS485 不能仅靠被动监听，需发送只读 EX-201S 请求；CAN 通过轮询 MCP2515 接收缓冲并按 CAN_USER 识别规则确认，必要时发送协议规定的只读发现请求。

只有完整通过协议校验的报文才能计为一次链路确认，建议连续确认两次后锁定。锁定后不因单个异常报文切换；连续失败达到门限时，MfcTask 先通知 ControlTask 安全停机并撤销旧事务，安全状态确认及重探测延时到期后才解除锁定。若两种协议都被有效确认、J17/J18 不一致或无法建立确定链路，则进入配置故障，不采用简单的“先到先得”。

统一业务层使用设定流量、读取状态和关断接口；EX-201S 或 CAN_USER 层负责编解码；UART 或 MCP2515 层只负责传输。版本信息应同时报告工程版本、当前链路状态、锁定依据和最后确认时间。MFC CAN_USER 与上位机 CAN0 应用协议分别管理。

## 6. FreeRTOS 初步任务方案

对应流程图见 [主板软件运行流程-FreeRTOS.md](<doc/Design Document/主板软件运行流程-FreeRTOS.md>)，包括运行时链路探测与锁定、三个任务协作、RS485 EX-201S 通信流程与状态图，以及 CAN_USER 流程、整机控制状态和阀门互斥切换。

建议使用三个业务任务；六台流量计使用六个通道对象，由一个通信任务管理。FreeRTOS 的 Idle 等系统任务不计入这三个业务任务。

| 任务 | 建议相对优先级 | 触发方式 | 主要职责 |
| --- | --- | --- | --- |
| ControlTask | 高 | 控制命令、故障通知、状态机期限 | 唯一的九阀输出写入者；处理启停、联锁和过程状态；向流量计任务发请求 |
| MfcTask | 中高 | 请求队列、探测/轮询期限、UART 通知及 SPI 状态轮询 | 独占 SCI2 与 SPI1/MCP2515；探测并锁定 EX-201S 或 CAN_USER；管理六通道、超时重试、采集、离线检测及安全重探测 |
| HostCanTask | 中 | MCU CAN 接收通知、回复与上报请求 | CAN 报文解析、命令合法性检查、提交控制请求、返回设备快照及执行结果 |

此优先级关系是初步建议。MfcTask 必须限制单次处理量并适时阻塞，使上位机命令不会被持续采集饿死；流量计 CAN 链路还应验证最坏调度延迟不会造成接收缓冲溢出。

运行流程：

1. 复位后尽早设置阀门及阀组电源为经硬件确认的安全输出状态；初始化时钟、GPIO 和基础驱动。
2. 初始化上位机 CAN0、SCI2、SPI1/MCP2515、收发器控制和终端策略。初始化不应长时间等待流量计在线。
3. 创建静态队列、同步对象、三个任务，启动调度器。
4. MfcTask 在调度器启动后监听 CAN_USER，并按地址发送无副作用的 EX-201S 只读探测；连续确认后锁定有效链路，再逐台识别和配置流量计。ControlTask 在探测期间保持安全输出；HostCanTask 始终提供状态查询和停机入口。
5. 就绪后接受启动或设定请求。HostCanTask 先确认请求收到，ControlTask 执行联锁和过程逻辑；需要设备交互时交给 MfcTask，完成后再返回执行结果。
6. MfcTask 周期采集，发布结果或故障事件；ControlTask 根据状态决定后续动作；HostCanTask 响应查询并按已定义协议上报变化。
7. 停机或故障时优先处理外部阀门和待执行命令，再异步请求流量计内部关闭及零设定；不得等串口或 CAN 事务超时后才处理外部阀门。

任务间通过有界队列传递请求和结果，状态快照使用短临界区或适当同步。ControlTask 不阻塞等待设备通信。中断只做必要的数据搬运、状态记录和允许的 FreeRTOS 通知，不执行复杂协议解析或阻塞调用。

RS485 由 UART 中断通知数据与发送完成，MfcTask 推进 EX-201S 组帧、发送、接收至 CR、累加校验和检查、OK/NG 处理及有界恢复。应答超时与残帧恢复使用独立期限。上位机使用 MCU 内置 CAN 中断；MFC CAN_USER 使用 SPI 轮询 MCP2515，服务期限独立于六路采集周期。

关键停机/故障请求应有不会被普通采集请求挤掉的锁存标志或独立通知机制；普通队列满时返回忙或失败。看门狗依据关键任务心跳和期限健康状态统一管理，不能仅因 Idle 仍运行就一直喂狗。具体监控放置及超时值在调度预算确认后确定。

## 7. 六路流量计管理

每个通道保存通道号、协议类型、设备 ID、启用状态、气体、量程、单位、小数位、目标值、已确认值、实际流量、内部阀状态、报警及有效数据时间戳。外部阀的命令状态与仪器内部阀状态分别维护。两种通信方式均由一个 MfcTask 管理六个通道对象。

### 7.1 EX-201S 电文

标准串口 9600 bit/s、8N1，实机 OPTION 优先。MCU 是唯一请求发起方，拟用 ASCII ID 001–006，逐台确认。请求和响应如下：

```text
请求：@ + ID(3字符) + 命令(4字符) + 数据 + 校验和(2字符) + CR
应答：% + ID(3字符) + 命令(4字符) + OK/NG + 数据 + 校验和(2字符) + CR
```

校验和为起始字符至数据末尾全部字节之和的低 8 位，再转为两位十六进制 ASCII。CR 是 0x0D；例 @001WVSS155<CR> 的校验字段为 55，%001RVSSOK1CF<CR> 为 CF。同一时刻只有一个在途请求；有效 OK 更新对应参数，有效 NG 报告拒绝，无效帧不更新缓存、不延长绝对应答期限。

### 7.2 EX-201S 命令及实现边界

| 业务 | 命令 | 处理要求 |
| --- | --- | --- |
| 量程、小数位、单位 | RMFS / RDPP / RFRU | 初始化读取；流量等于尾数乘以 10 的负小数位次方 |
| 数字控制来源 | RFSM / WFSM | 0 数字、1 模拟；按允许条件设置并读回 |
| 实时流量 | RCFR | 按符号、小数位与单位解码，保存采样时间 |
| 数字设定值 | RSFD / WSFD | 四位十进制尾数，检查量程；写后确认，必要时读回 |
| 当前设定 | RCFS | 与数字 SP0 区分，结合控制来源核对 |
| 内部阀命令 | RVSS / WVSS | 0 全开、1 调节控制、2 全关；不可把全开当作正常调节 |
| 内部阀状态、开度 | RCVS / RCVO | 与外部 V1–V9 的命令状态分开记录 |
| 设备报警 | RALM | 0 正常；1 传感器，2 阀门过热，4 设定记忆回路，组合值相加 |

- 本项目不使用 Modbus。接收以起始字符和 CR 确定帧边界，不使用 CRC16 或 RTU 的 t1.5/t3.5 判帧。
- UART 发送缓冲空不等于最后停止位完成，必须等待真正发送结束后转接收。应答期限、最大帧长和残帧恢复均有界，超时值依据实机响应能力确定。
- 有效 NG 表示设备拒绝本次操作，不能直接判离线；NG 具体原因若报文未提供，不得编造错误码。只有匹配且校验通过、数据结构正确的 OK 才更新相应业务值。
- 写应答丢失时设备可能已经执行。按命令的幂等性决定先读回还是重试；禁止重复执行未确认可重复的配置操作。
- 协议没有线上事务序号；同地址同命令的迟到应答可能与新事务混淆。超时后按设备最大响应时间留恢复窗口，内部请求号仅用于阻止旧结果推进新的过程。
- 手册存在 ID 范围 01–99 与 001–009、RCFR 数据长度、写指令“响应：无”与通用 OK/NG 格式的歧义，联调时逐项向厂家或实机确认。
- 模拟强制阀输入可能优先于数字设定，必须核对接线和数字控制权。停机先由 ControlTask 关闭外部供气阀，再由 MfcTask 调度内部关闭和零设定。

### 7.3 CAN_USER 协议边界

MFC CAN 应用层固定采用用户自定义 CAN_USER，MfcTask 经 SPI 操作 MCP2515 完成收发。协议名称已确认；节点与六通道映射、波特率、标准/扩展 ID、命令/响应/上报字段、长度、数据类型、缩放、字序、错误、心跳与业务确认待用户协议附件补齐。

经典 CAN 单帧最多 8 字节数据，必要时按用户协议实现分段、序号及重组超时。CAN 硬件 ACK 或发送完成不等于业务执行完成。对端必须实现同一 CAN_USER 协议，不推定现有 EX-201S 原生支持 CAN_USER，也不默认把 ASCII 电文直接封装成 CAN。

### 7.4 六路调度和恢复

关断优先，控制其次，采集兼顾各启用通道；事务、重试及接收恢复均有界。离线设备降低探测频率，健康通道继续服务。停止撤销旧开阀与非零设定，旧结果不推进新启动。RS485 耗时按电文长度、字符位数、波特率和设备处理时间计算；CAN_USER 按帧负载、SPI 服务期限和应用确认时间单独预算。

图中气体及流量标注须核对铭牌与工艺，设备预热按实际 EX-201S 说明执行，预热期间仍保留通信和停机入口。

## 8. 九阀控制与过程状态

V1 至 V6 为支路外部阀；V7、V8、V9 为混气管后的通路阀。MCU 软件统一控制外部阀，流量计内部阀状态作为另一类参数记录。

按用户最新说明，将 V7、V9 作为同一个逻辑阀组 `ValveGroup79`，明确联锁规则如下（1 为开，0 为关）：

```text
V7 = V9
V7/V9 阀组打开 ⇒ V8 必须关闭
V8 打开 ⇒ V7、V9 必须同时关闭

合法条件：(V7 == V9) && !(V8 && (V7 || V9))
```

按 `(V7,V8,V9)` 排列，只允许以下三个目标组合；其余组合均不允许：

| V7 | V8 | V9 | 含义 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 三阀全关，也作为互斥切换的中间目标 |
| 1 | 0 | 1 | V7/V9 阀组打开，V8 关闭 |
| 0 | 1 | 0 | V8 打开，V7/V9 阀组关闭 |

ControlTask 统一执行组操作：

- 打开 V7 或 V9 的请求都解释为“打开 V7/V9 阀组”：先关闭 V8，满足关闭条件并再次通过联锁后，再同步下发 V7、V9 开命令。
- 关闭 V7 或 V9 的请求都解释为“关闭 V7/V9 阀组”，同时下发两阀关命令；不会因此自动打开 V8。
- 打开 V8 时，先同步关闭 V7、V9，等待两阀均满足关闭条件后，再打开 V8。关闭 V8 不会自动打开 V7/V9。
- 批量设置的完整目标必须通过上述合法条件，显式指定 V7/V9 不一致或两组同时打开的请求应拒绝。单阀指令先转换成组操作，再生成合法目标；不能分别放行两个互相冲突的开阀请求。
- 初始化、自动过程、手动控制及故障处理都使用同一组目标和联锁入口；关闭 V7/V9 时撤销该组未完成的打开请求。

切换互斥通路采用“先关后开”：`101 → 000 → 010` 或 `010 → 000 → 101`。等待由非阻塞状态机管理，期间仍响应停止与故障；真正打开前再次检查请求有效性和联锁。

V7/V9 的目标值在同一次组操作中更新，输出层同步提交两阀命令，不将它们作为两个独立业务动作。这里的同步是软件命令要求；机械动作时间、输出更新偏差和反馈能力仍需实板确认。不能把“GPIO 已改变”直接报告为“机械阀已到位”；当前资料尚未确认九阀具有位置反馈。

建议状态包括 INIT、WARMUP、READY、STARTING、RUNNING、STOPPING、FAULT。所有开阀路径都应经过 ControlTask 联锁；上位机的手动指令也不能绕过。异常后撤销未完成的开阀及非零流量请求，避免恢复通信时执行旧命令；复位或故障解除后不自动恢复送气。

安全停机暂按“撤销开阀请求、关闭供气相关外部阀、异步请求流量计关断”设计。是否需要主动排空、V7/V8/V9 的停机位置及阀组电源处理顺序，需由气路工艺明确，不能默认所有场景下开排空阀或全部断电就是最终安全状态。

## 9. 上位机协议与资源约束

上位机通信固定为 CAN。需要定义设备标识、协议版本、启停、六路设定、阀门操作、状态查询和报警等报文；CAN 波特率、标准/扩展 ID、分包、心跳周期和超时策略尚待确定。涉及多帧命令时，应完整重组和校验后再执行，不能边收边开阀。

状态上报至少区分：请求已接收、操作已执行、设备已确认。状态快照应包含过程状态、九阀命令状态、六路在线状态及参数、数据有效标志、数据时间戳和故障码；没有物理反馈时不伪造阀门实际位置。

MCU 项目资源基线为 48 MHz Cortex-M4F、256 KB Flash、32 KB SRAM、8 KB Data Flash。FreeRTOS 先采用静态任务栈和有界缓冲区，按链接映射及实测栈水位核算内存；避免六路各建一套任务与大缓冲。配置变更才持久化，不周期写入运行采样值。

用户提出整机待机功耗小于 100 W、环境温度 −10 ℃ 至 +40 ℃。这些是整机验证目标，不能仅凭使用 RTOS 或 MCU 的规格判定满足；需结合六台流量计、阀门、供电和散热验证。流量计自身允许的使用温度及准确度条件也应单独核对。

## 10. 待确认项与联调顺序

| 项目 | 当前状态及下一步 |
| --- | --- |
| 上位机装配 | U5 已焊、U2 未焊来自用户说明；核对 U4 两侧信号及 R8/R9/R11/R13 装配 |
| 流量计 RS485 极性 | 核对 R14/R17/R148/R149 的实际装配，逐端口做通断检查并形成线束表 |
| MFC_EN2 电路 | 测量 U7 的集电极/发射极、U17 DE、U22 STB 在两种输入下的电压，核对是否满足门限，必要时由硬件修正 |
| 收发器实际型号与供电 | U17 标注 SP3485EN、供电网络标为 5V4；核对实物型号与额定供电兼容性，上位机预留 U2 同类项也需记录 |
| 接地与终端 | 核对 GND3/GND4/GND5/FG、J12 MFC-ISO 的实际连接；确定两条总线各自的终端位置与控制极性 |
| MCP2515 接线 | 确认实板是否与图一致，INT 是否未接、Y1 是否 8 MHz，以及 SPI 实际外设复用 |
| MFC CAN_USER | 自定义协议名称已确认；补齐节点、波特率、ID、业务字段、确认/重试/心跳及兼容对端，完成独立联调 |
| EX-201S 协议参数 | 核对实际 OPTION、串口、ASCII ID、RCFR 长度、写回应、量程换算与最大响应时间；不再索取 Modbus 寄存器表 |
| 设备参数 | 核对六台地址、型号、气体、量程、单位、接口选件及模拟强制控制端的接法 |
| 阀门与工艺 | 核对 V1–V9 对应线束、常开/常闭属性、有效电平、阀组电源控制、动作时间、反馈及各模式动作顺序 |
| 上位机 CAN 协议 | 确定波特率、ID、请求/响应、状态上报、心跳与失联后的停机规则 |
| 实时性与资源 | 确定允许的控制延迟、采集刷新周期、离线判定时限，再确定任务周期、优先级、队列和栈大小 |

联调建议依次为：断电核对跳线、线束和装配 → 测量使能与终端控制 → 上位机 CAN 单链路验证 → 单台流量计通信与关断验证 → 六台总线负载和掉线验证 → 九阀联锁及中途停机验证 → CAN_USER 版本按用户协议与兼容对端单独验证 → 长时间运行、复位、通信异常与环境测试。

当前验证范围为原理图阅读、引脚和网络交叉核对，以及设备资料核对；尚未进行实板测量、固件编译或运行测试。
